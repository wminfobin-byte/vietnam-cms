3 취소접수

1-2 고객상담 > [상담]

취소접수 (배송 전/후)

배송대기 · 배송중 상태의 건을 상담원이 취소접수로 전환. 배송전취소와 배송후 수취거절을 동일하게 처리.

취소접수뿐 아니라 중도해지 · 반품방식 변경 · 위약금 협의/입금 등 반품 관련 처리는 모두 상담창의 상담상태 선택(대분류→소분류) + 이력 작성 방식으로 처리 (국내 CMS 동일). 아래는 국내 상담상태 선택 화면.

  • 대분류 반품 선택 시 소분류로 상황별 처리 노출: 취소접수(배송전/수취거절) · 중도해지(반품접수) · 반품방식 변경 · 위약금 협의·수정 · 위약금 입금.
  • 소분류는 현재 고객상태 + 로그인 사용자의 (팀, 타입)에 따라 가능한 것만 노출 — 예: 위약금 협의=미납담당자재무 · 아웃바운드(매니저), 위약금 입금=재무담당자재무 · 관리자. 전체 조건은 12번 참조.
  • 저장 시 상담 이력에 누적 기록 (일시 · 담당자 · 대분류>소분류 · 내용).
  1. 취소접수 — 고객상태 배송대기/배송중 건에서 상담상태 반품 > 취소접수(배송전취소 / 배송후 수취거절) 선택 → 고객상태 취소접수 + 이력.
  2. 이후 3-6 환불에서 환불요청 → 환불승인 → 취소로 종결.
상태전이 배송대기/배송중 → 취소접수 → 환불요청 → 환불승인 → 취소

5 구매완료 처리 — 송장 업로드 / 입금처리

신규 페이지

구매완료 = ① 송장 업로드 + ② 입금처리

구매완료는 ① 송장 업로드(물건 발송)와 ② 입금처리(입금 확인)가 모두 완료되어야 성립. 둘 다 완료되면 구매완료가 되고, 그 시점부터 중도해지(반품) 가능.

현재 화면 없음 — 신규 개발 송장 업로드 · 입금처리 화면이 베트남 CMS에 존재하지 않음.
  1. ① 송장 업로드 (4-6) — 송장 미등록 건 목록 → 다중 선택 → [선택 건 송장 업로드] (또는 행별 송장번호 입력). 처리 시 물건 발송 완료로 표시. 노출: 매니저 · 관리자아웃바운드매니저 / 관리 · 관리자.
  2. ② 입금처리 (3-9) — 입금 미확인 건 목록 → 다중 선택 → [선택 건 입금처리]. 가상계좌 업로드 양식(11번)과 연계 가능. 노출: 재무담당자재무 · 관리자.
  3. ③ 구매완료 처리 (3-10) — 송장(배송중) + 입금이 모두 완료된 건을 확정 → 고객상태 구매완료. 이때부터 중도해지(상담창) 진행 가능. 노출: 관리자관리 · 관리자.
①②는 처리 순서 무관(독립). 고객상태는 배송대기 → 배송중(송장) → 구매완료(3-10)만 사용하고, 입금은 고객상태가 아니라 별도 플래그로 관리함. (구매대기·입금완료 같은 별도 상태값 없음)

1-2 DB 리스트

용어 주의 — [반품취소] = 반품 철회 이 버튼은 "반품을 시작"하는 버튼이 아님. 중도해지 접수까지 진행한 건에서 고객이 "그냥 사용하겠다"고 할 때 반품을 철회해 다시 구매완료로 되돌리는 버튼임.
  1. 중도해지(반품접수) 시작은 상담창에서 선택 — 상담상태 반품 대분류 > 중도해지(반품접수) 소분류 선택(3번 상담창 방식). 선택 시 반품접수창(7번, 국내 동일) 진행.
  2. [반품취소] 버튼(철회)은 진행 중인 중도해지~환불요청 구간에 노출팀 무관 · 타입 아웃바운드매니저 — 매니저 계정에만 표시. 클릭 시 확인 후 구매완료로 복귀(이력 기록).
  3. 고객상태 컬럼에 진행상태 표시: 중도해지 · 입고대기 · 반품입고 · 위약금 미입금 · 위약금 협의 · 위약금 입금 · 환불요청 등.
처리 위치 반품입고 = 4-1 입고 / 5-2-1 입고업로드 / 4-3 수동입고처리, 환불 최종처리 = 3-6 환불에서 진행. 따라서 1-2 기능 컬럼에는 [상담] · [중도해지 승인] · [반품취소(철회)] · [고객 관리]만 둠.

7 국내 CMS 반품접수창 (참고 템플릿)

"국내 CMS 반품접수와 동일"의 실제 기준 화면. 국내 접수창은 위저드가 아니라 하나의 긴 스크롤 페이지이며(아래 4장은 길어서 잘라 캡쳐), 위→아래로 ①접수조건 → ②위약금 정산 → ③결제·환불 → ④상담내용을 한 화면에서 작성·저장. 베트남은 청약철회/계약해지 구분이 없고 위약금결제 · 기기반납 2가지만 있음. 아래 초록 박스가 베트남 적용 포인트.

참고

국내 반품접수창 — 한 페이지 (4개 영역)

① 접수 조건 · 위약금 산정 기준 — 반품접수창 上

  • 위약금 산정 기준일 — 날짜 + [오늘로 설정하기]. 이 날짜 기준으로 위약금 · 환불 계산(고객 합의일 입력).
  • 해지 형태(국내) — 청약철회 / 중도해지.
  • 계약 정보 및 납부 현황 — 월 납부액 · 잔여 회차 · 잔여 총액 · 계약일 · 이용권 발행일 · 요청일.
  • 사은품 및 비용 정산 — 품목/수량/처리상태([미개봉][개봉])/정가/청구율/경과일수/청구액/조정(할인)/최종금액/수거여부.
  • 수거(반품) 방식 — 택배 회수 요청 / 고객 선불 발송 → [위약금 계산하기].
베트남 적용 — 청약철회/계약해지 구분 없음. 페이지 상단에서 반품방식(위약금결제 / 기기반납)을 먼저 선택. 운송비는 기기반납일 때만 부과. '돈버는학습' 등 국내 전용 항목 제외.

② 위약금 및 비용 정산 (계산 결과) — 반품접수창 中

  • 위약금 산식 — 예: "0원 (중도해지 30일 이내, 기본위약금 없음)"처럼 적용 규칙 자동 표기.
  • 항목 — 1회차 할인금액 / 면제 환급금 / 미납원금 / 연체가산금 / 기본 위약금 / 돈버는 학습 반환금 / 운송비. 각 산정금액 · 조정(할인) · 최종금액.
베트남 적용 — 항목 구성을 베트남 위약금 정책에 맞춰 재정의 필요. 잔여 할부금 / 면제 환급 / 운송비가 핵심. 금액 단위 동(VND) 표기.

③ 결제 및 환불 수단 — 반품접수창 下

  • 위약금 최종 청구액 — 상단 강조(예: 104,900원).
  • 기존 승인 내역 — 무통장 입금자명 / 결제금액 / 카드사 · 카드번호 · 유효기간 / 할부 / 결제방법.
  • 수단 탭 — [청구(카드)] / [청구(계좌)] / [환불(계좌)]. '수금관리 카드정보 사용' 버튼.
  • 안내 체크리스트 — 반품 택배비 / 사은품 개봉 비용 / 파손 · 훼손 수리비용 안내 확인.
베트남 적용 — 위약금 입금(재무담당자) · 환불(계좌)이 여기서 처리. 가상계좌/금액 양식 업로드(11번)와 연계. 베트남 결제수단(카드/계좌)에 맞게 탭 구성.

④ 상담내용 확인 · 저장 — 최종

  • 이름/전화번호 · 기기/사은품 개봉여부 · 위약금 · 위약금 결제방법 및 할부개월 · 픽업유무 요약.
  • [저장하기] 시 상담이력 기록 + 고객상태 전환.
베트남 적용 — 저장 시 고객상태(중도해지/입고대기/위약금 미입금 등) 전환 + 1-2 리스트 진행상태 컬럼 갱신.

8 반품방식 선택 · 전환

반품접수 창

기기반납 / 위약금결제 선택 및 상호 전환

중도해지 접수 후 반품 방식을 선택. 선택 이후에도 고객 요청 시 상호 전환이 가능해야 함.

참고 화면 — 7. 국내 반품접수창 ①의 수거(반품) 방식 설정(택배회수=기기반납 / 위약금 계산=위약금결제).
  1. 반품방식 선택 — 기기반납(9번) 또는 위약금결제(10번).
  2. 승인 전 · 진행 중 방식 전환 버튼 제공. 노출: 매니저팀 무관 · 타입 아웃바운드매니저.
  3. 중도해지 승인도 매니저타입 아웃바운드매니저에서만 가능.
협의 필요 전환 허용 시점(승인 전까지만 vs 진행 중 언제든)과 이미 입력된 위약금/입고 데이터 처리 정책.

9 기기반납 처리

반품접수 창

기기반납 (입고대기 → 반품입고)

기기 회수를 통한 중도해지. 입고 확인 후 환불 처리로 이어짐.

참고 화면 — 7. 국내 반품접수창 ①(수거방식 · 사은품 수거여부).
  1. 중도해지 승인(매니저타입 아웃바운드매니저) → 고객상태 입고대기.
  2. 기기 회수 · 입고는 4-1 입고 / 5-2-1 입고업로드 리스트 / 4-3 수동입고처리에서 처리 → 반품입고 전환. (1-2 기능 컬럼 버튼 아님) 노출: 매니저 · 관리자아웃바운드매니저 / 관리 · 관리자.
  3. 이후 3-6 환불에서 환불요청 → 환불승인 → 중도해지(기기반납) 종결.

10 위약금결제 처리

반품접수 창

위약금결제 (미입금 → 협의/수정 → 입금)

기기 회수 없이 위약금 결제로 중도해지. 단계별로 담당 권한이 다름.

참고 화면 — 7. 국내 반품접수창 ② · ③(위약금 산정 · 청구/환불).
  1. 중도해지 승인(매니저타입 아웃바운드매니저) → 고객상태 위약금 미입금 추가.
  2. 위약금 협의·수정 — 미납담당자재무 · 아웃바운드(매니저) · 상담상태. 위약금 금액 협의/수정.
  3. 위약금 입금 — 재무담당자재무 · 관리자 · 상담상태. 입금 확인.
  4. 이후 환불요청 → 환불승인(4번) → 중도해지(위약금) 종결 + 컨텐츠 자동 사용중단.
협의 필요 위약금 산정 기준(잔여 할부금/정책)과 협의·수정 시 변경 이력 보존 여부.

11 가상계좌 · 금액 양식 업로드

신규 / 연계

할부금 · 위약금 양식 업로드

할부금 및 위약금을 가상계좌/금액 양식(엑셀 등)으로 업로드해 반영. 1차는 수동, 이후 자동반영 확장 계획.

  2. 업로드 데이터로 위약금 입금(10번) · 구매완료(5번) 상태 반영.
  3. 1차는 수동 업로드, 추후 자동반영으로 확장.
협의 필요 양식 컬럼 정의(주문키 · 가상계좌 · 금액 · 입금일 등).
